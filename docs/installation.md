# Installation

## Readiness

CPU acceptance covers the source export, synthetic loopback traffic and a built wheel installed in a separate environment. The current source suite and the wheel installed into a fresh isolated environment each passed 690 tests with five skips for absent torch or Windows symlink permissions. The installed run used site-packages without checkout import contamination. Its generated 256-option configuration was parsed unchanged by the gateway and the standalone engine helper. These checks do not establish a clean GPU launch or public endpoint security.

This runtime serves our production deployment on two GB10 nodes, launched from this package with the recorded image and serving profile. The maintainer-host deployment passed live checks for typed decisions (including the wide-label lane at 17, 26, 27, 32, 64, 128 and 256 options, with a 257-option request refused), chat, tool calls, streaming and request-bound capture, and its earlier acceptance history includes a real rollback to the previous engine. The router there was generated by `qfn_decision.configure`, with the listen address changed for LAN access.

That is a launch on our own hosts, not a clean installation on a fresh machine. The exact installed runner and three inherited overlays have known hashes, and the overlays are included. The tested arm64 image has a recorded repository digest, but its complete source commit and build recipe are not recovered: the version suffix `8e685d198` is not a commit in `vllm-project/vllm`, and we have not checked that the digest can be pulled from a public registry. `runtime-dependencies.json` records unknown pins as null rather than substituting current mainline code.

Model redistribution is held separately for license and provenance review. The derivative model card's Apache declaration is not evidence that the official base permits unrestricted commercial use.

## CPU gateway

Use Python 3.12 or newer. Install NumPy and, for tests, pytest using your normal environment workflow. The project metadata declares these dependencies. No GPU libraries are needed for gateway imports or NumPy tests. Torch is optional for the torch-CPU capture-writer test module.

For source-only execution without installation, run from the checkout with `PYTHONPATH` set to its absolute `src` directory. An editable installation supplies the same package imports. Examples below use POSIX shell syntax; on Windows use absolute native paths for Python arguments.

```sh
export PYTHONPATH="$PWD/src"
export PYTHONDONTWRITEBYTECODE=1
python -m pytest
python -m qfn_decision.configure --help
python -m qfn_decision.hybrid --help
```

## Engine inputs

The tested engine used Linux arm64, two GB10 workers, TP2 with expert parallelism, vLLM `0.1.dev20073+g8e685d198` and torch `2.13.0+cu130`. The image reference is recorded in the dependency manifest. The known serving profile used MTP3, FP8 KV, context 1,000,000, maximum sequences 8, maximum batched tokens 8192 and memory utilization 0.73. These are recorded settings, not a promise that they fit another machine or build.

The inherited overlays are required by this tested profile:

| Exported file | Engine package destination |
|---|---|
| `engine/overlays/ple_layer_patched.py` | `vllm/models/qwen3_8_flash_next/nvidia/ple_layer.py` |
| `engine/overlays/qsa_ops_patched.py` | `vllm/models/qwen3_8_flash_next/nvidia/ops/qsa.py` |
| `engine/overlays/qsa_nvidia_patched.py` | `vllm/models/qwen3_8_flash_next/nvidia/qsa.py` |

The PLE resolver uses `PLE_QUANT_OVERRIDE=fp8` for the checkpoint's FP8 PLE table. The QSA overlays support the tested FP8 KV path. Do not substitute the PLE file from a different local recipe: it has different bytes and may have a different license. These files came from the MIT-licensed recipe snapshot, not the separate AGPL-3.0 recipe.

Keep the matching image's model implementation, parser and quantization dependencies. The recorded ordinary-generation parsers were `qwen3` reasoning and `qwen3_coder` tool calls. Do not apply this bundle to a different source file by disabling the hash guard.

The full checkpoint is an external input selected by `MODEL_DIR`. The pinned derivative snapshot is `lychee888/Qwen3.8-Flash-Next-Uncensored-NVFP4-FP8PLE@1b3c3cedc14fb3bee4294dea5e3515af74b8268a`. Its shard index intentionally replaces one original shard with ten FP8 PLE shards. Do not infer a missing file from an absent original `model-00002` shard name; use the snapshot's actual index.

## Build the capture call-site patch

Two options exist. Use the bundled generated runner if you are on the exact tested build; otherwise rebuild it from your own pristine source.

**Drop-in.** `engine/generated/model_runner.py` (92,206 bytes, SHA256 `0baf739d…`) is the patch output for the tested runner. Install it as `vllm/v1/worker/gpu/model_runner.py` after confirming your upstream file matches 91,240 bytes with SHA256 `f08ba0f5…`. If either check fails, do not force it; rebuild instead.

**Rebuild.** Supply the pristine installed runner from the matching engine as `VLLM_RUNNER_SOURCE`. It is not bundled as a second vLLM tree.
 from the matching engine as `VLLM_RUNNER_SOURCE`. It is not bundled as a second vLLM tree.

```sh
python engine/build_capture_patch.py \
  --src "$VLLM_RUNNER_SOURCE" \
  --out build/model_runner.py \
  --source-version '0.1.dev20073+g8e685d198' \
  --checksums build/runner.sha256 \
  --meta build/runner.json
```

The input must be 91,240 bytes with SHA256 `f08ba0f5ad41c8b9d5145fb1fba115ffd97f35f1e59017602e235ec0823abce8`. The generated runner is `0baf739dbc1b6fefbc3364ce79bf5de55b564b13d5bbea451eb1a664f70fca30`. The builder verifies source bytes, LF anchors, absence of its marker and AST statement deltas. It refuses source/output aliases. The version argument is an operator declaration, not a probe of an installed engine.

## Generate local configuration

Choose new paths under your control. The generator refuses to overwrite its three output files.

```sh
export MODEL_DIR=/srv/models/qwen-flash-next
export CAPTURE_DIR=/srv/qfn/captures
export ENGINE_URL=http://127.0.0.1:8897
export ENGINE_MODEL=qwen3.8-flash-next-uncensored
export TOKENIZER_REVISION=1b3c3cedc14fb3bee4294dea5e3515af74b8268a
export WIDE_CHOICE=1
export WIDE_CATALOG_PATH="$PWD/configs/wide-label-catalog.json"
python -m qfn_decision.configure --out runtime
```

`CAPTURE_DIR` is the absolute engine-visible path. If the gateway sees the same files at a different absolute path, set `GATEWAY_CAPTURE_DIR` before generation. The capture config does not expand environment variables internally. `MODEL_DIR` is for the operator's separate engine launch; the config generator does not inspect or validate weights.

## Enable the wide-label lane (17 to 256 options)

The recipe above enables all 256 options explicitly with these settings. The generator itself leaves wide options disabled unless the operator supplies them:

```sh
export WIDE_CHOICE=1
export WIDE_CATALOG_PATH="$PWD/configs/wide-label-catalog.json"
```

`WIDE_CATALOG_PATH` must be absolute. The configured file must be readable at that exact absolute path inside every engine worker and by the CPU gateway, with matching bytes. The generator writes two separate `wide_choice` blocks: the gateway block carries the `max_options` cap, and the engine capture block omits it; copy them from the generated files, and do not copy the gateway block into the capture config. The engine capture configuration is read once at startup, so enabling (or later changing) the wide lane needs a coordinated engine restart. Full contract, catalog pins and capture records are in [api-wide-labels.md](api-wide-labels.md).

`configs/decision_api.json`, `decision_api.chat_letters.example.json`, `protocol.json` and `templates.json` retain the lower-level protocol/test contracts, including legacy surfaces. They are not instructions to enable a trained head or native score. The supported launch configuration is the generated `gateway.json`, checked by `qfn_decision.hybrid`.

## Mounts and process ownership

Prepare a separately owned engine. Do not start a second engine on top of an existing deployment. This project intentionally contains no SSH launcher, container-cloning script, production supervisor or automatic rollback controller.

On the matching engine workers, provide these files at the engine's actual Python package paths. The recorded image used `/usr/local/lib/python3.12/dist-packages/`:

1. Generated `build/model_runner.py` as `vllm/v1/worker/gpu/model_runner.py`, read-only.
2. `engine/qfn_capture_runtime_production.py` as `vllm/v1/worker/gpu/qfn_capture_runtime.py`, read-only. The filename at the destination is important because the runner imports that module name.
3. The three inherited overlays above, read-only.
4. Generated `capture.json`, read-only, at a stable absolute config path.
5. The configured capture directory, writable by the engine and readable by the CPU gateway. Each worker that exports head rows needs a writable `artifacts/base_rows` directory too. The gateway reads the driver's committed capture pairs; no SSH record fetcher is used.

Set `QFN_CAPTURE_ENABLE=1` and `QFN_CAPTURE_CONFIG` to the mounted absolute capture config path on the engine workers. The accepted two-worker staging mounted the generated runner, helper and config on both workers. Preserve the matching distributed-engine setup; this CPU export does not validate a new parallel topology.

The helper is off by default and only captures marked `cmpl-qfn-` requests. It reads the terminal prefill row after raw logits are computed and before grammar, sampling or temperature processing. It refuses unproven speculative-row alignment. The gateway verifies request identity, prompt-token digest, terminal position, row order and inactive masks before returning probabilities.

Launch the engine once using the separately reviewed engine configuration. Then launch the CPU gateway:

```sh
python -m qfn_decision.hybrid --config runtime/gateway.json --check
python -m qfn_decision.hybrid --config runtime/gateway.json
```

The `--check` command validates local configuration without starting a listener. Health is not proof of a GPU inference result. The launcher refuses H1 artifacts, enabled LoRA arms and thinking-enabled or non-letter surfaces.

## Exact-route frontend

Run nginx independently, with a writable prefix directory. The generated config binds `127.0.0.1:8888`; the engine and gateway default to loopback ports 8897 and 8890. `FRONTEND_PORT` and `GATEWAY_PORT` can be set before generation.

```sh
nginx -p "$PWD/runtime/" -c nginx.conf -t
nginx -p "$PWD/runtime/" -c nginx.conf
```

Only `/v1/decide`, `/v1/systemone` and their trailing-slash forms go to the gateway. Query strings do not change route selection. Other methods and paths, including models, tools and streaming chat, go to the engine. Proxy buffering and request buffering are disabled; authentication headers and request IDs are forwarded. Authentication and TLS must be provided separately before exposing this loopback service. The gateway does not validate a caller's API key.

Nginx was not installed in the preparation environment, so the exported nginx config has static route assertions but no new `nginx -t` receipt. The gateway's retained loopback tests exercise body forwarding, SSE and cancellation using synthetic upstreams.

## Capture retention

The production helper uses retained-storage accounting, reservation ownership and an active-publication fence. Default generated limits are 4,096 retained pairs, 32 GiB retained bytes, 10 GiB free-disk reserve and 256 KiB per-record reserve. Capture requests fail closed when capacity is exhausted; deleting files is not part of a request.

Retention is a separate operator action and defaults to dry run:

```sh
python engine/retention.py --root "$CAPTURE_DIR" --ttl-seconds 86400 --grace-seconds 3600
# Review the audit before using --execute with explicit deletion bounds.
```

It only considers completed top-level NPZ/JSON pairs matching the helper's naming rule. It does not recurse into artifacts, follow symlinks, remove incomplete pairs or delete current files. A valid future `BENCHMARK_HOLD.json` can block collection; malformed or expired holds warn rather than disabling the quota indefinitely. Revalidation at deletion checks identity and the hold again.

Do not force-clear an active writer. A stalled publication keeps its reservation until it finishes or the owner process is confirmed stopped; the helper does not promise bounded recovery from stalled I/O. Treat the capture root as private: it contains prompt fingerprints and internal features. Bound artifact exports and any archives separately, since this retention tool excludes subdirectories.

## Remaining clean-install gates

- Recover the full source commit and build recipe corresponding to the recorded vLLM image. The full commit mapping and image build manifest are absent from this release; the installed runner is an external, hash-pinned build input.
- Verify image retrieval and a clean matching GPU engine boot with the PLE/QSA overlays and capture mounts. No fresh-machine GPU installation or host reboot test has been run.
- Exercise real typed and concurrent ordinary chat/tool/SSE traffic against that packaged engine. The current CPU results are not a live acceptance receipt.
- Run nginx configuration validation and exact-route traffic against this generated configuration.
- The current Windows installed-wheel check is complete. This does not establish a clean GPU engine installation.
- Verify the same installed path on each additional operating system you intend to support; the engine remains Linux arm64.
- Resolve model source revision and redistribution/commercial-use permissions. No code license in this repository overrides those conditions.
